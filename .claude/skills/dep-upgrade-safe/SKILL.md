# Safe Dependency Upgrade

調査ファーストで特定パッケージをアップグレードし、移行と動作確認まで行う。

## 手順

1. **依頼を整理する**: パッケージ名と現在→目標バージョンを特定し、それぞれ major / minor / patch に分類する。
2. **まず使用状況を確認する。** コードベースを grep して実際の import・使用箇所を洗い出す。未使用のパッケージなら、アップグレードではなく削除（`npm uninstall <pkg>`）を提案してそのパッケージについては終了する。
3. **破壊的変更を調査する**（メジャーアップ、または評判的に注意が必要なマイナーアップ）:
   - **目標バージョン**の changelog / GitHub Releases / 移行ガイドを取得する。API シグネチャは必ず目標バージョンに対して検証し、古い API がまだ使えると仮定しない
   - 破壊的変更を 1 件ずつ列挙し、このコードベースが影響を受けるかどうかの判定を付ける
4. **このプロジェクト特有の注意**:
   - `aws-amplify` / `@aws-amplify/*` はバージョン整合が必要。バックエンド関連（`amplify/` 配下が依存するパッケージ）を更新した場合は Sandbox の再起動と `amplify_outputs.json` の再生成を待つこと
   - Next.js のアップグレード時は `node_modules/next/dist/docs/` の該当ガイドを必ず確認する（プロジェクトルール）
5. **適用する**: `npm install <pkg>@<version>`（package.json の手編集はしない）。影響を受けるコードを移行する。エラーを黙らせるための `eslint-disable` や `@ts-ignore` は禁止 — 型を正しく直す。
6. **検証する**:
   - `npx tsc --noEmit` / `npm run lint` / `npm run build`
   - ランタイムエラーはビルドでは出ないため、`npm run start:local` で開発サーバーを起動し、影響範囲の画面を実際に確認する
7. **PR を作る**: feature ブランチを切り、調査結果（見つかった破壊的変更、影響あり／なしの判定、適用した移行内容）を PR 本文に含める。マージは人間が行う。
