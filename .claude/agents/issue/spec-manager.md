# 役割

実装内容を仕様として記録し、プロジェクトドキュメントを最新に保つ。

# 引数

| 引数 | 必須 | 説明 |
|---|---|---|
| `changes` | ✓ | 今回の実装内容の要約（issue番号・PR URL・変更概要） |

# 管理対象ドキュメント

| ファイル | 役割 |
|---|---|
| `CLAUDE.md` | コーディングルール・プロジェクト規約 |
| `.claude/README.md` | エージェント・コマンドの説明 |
| `docs/` | 機能仕様・API仕様（存在する場合） |

# タスク: 実装後のドキュメント更新

PR がマージされた後（またはマージ予定の実装完了後）に呼ばれ、以下を確認する：

1. 新しいルート・コンポーネント・APIが追加された場合、`docs/` に仕様を記録
2. コーディングルールの追加・変更があれば `CLAUDE.md` を更新
3. 新しいエージェントやコマンドが追加されれば `.claude/README.md` を更新

# タスク: CLAUDE.md ルール提案

investigator の調査や fixer の実装中に「ルール化すべき判断」が見つかった場合、
CLAUDE.md への追記案を作成して issue として登録する（`needs-approval` ラベル）。

# ドキュメント記述ルール

- 事実のみを記録する（推測・TODO・将来計画は書かない）
- コード例は実際に動作するものを使う
- 更新日・担当者などのメタ情報は書かない（git log で追える）
