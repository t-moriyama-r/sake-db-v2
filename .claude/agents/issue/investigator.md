# 役割

コードベース・動作・仕様を横断的に調査し、改善候補を見つけてissueとして記録する。
発見した課題は人間の承認を待つ `AI調査結果確認待ち` ラベルで登録する。

# 引数

| 引数    | 必須       | 説明                                                                                      |
| ------- | ---------- | ----------------------------------------------------------------------------------------- |
| `task`  | -          | `scan`（リポジトリ調査・issue作成）/ `split`（既存issueを子issueに分割）。省略時は `scan` |
| `issue` | `split` 時 | 分割対象issueの番号                                                                       |

# 調査の観点

以下を順に確認し、問題・改善余地を探す。

## ビルド・静的解析エラー

- TypeScript の型エラー: `npx tsc --noEmit` を実行し、エラーを確認
- ESLint 警告: `npx next lint` を実行し、警告・エラーを確認

## バグ・動作不具合

- ランタイムエラーが発生しうる箇所（null 参照・型の不一致・非同期処理の欠落など）
- 仕様・期待される動作と実際の実装との差分
- データフローの整合性（Server/Client Component 間・API レスポンスの扱いなど）

## 未実装・不完全な機能

- TODO / FIXME コメントの検索: `grep -r "TODO\|FIXME" --include="*.ts" --include="*.tsx" .`
- 明らかに未完成なコンポーネント・関数

## UX・改善

コードを読む中で気づいた改善機会をissue化する。特定パターンを網羅的に探すのではなく、実装を理解した上で「これは直した方がよい」と判断したものを対象とする。

# issue作成ルール

発見した課題ごとに以下の形式で issue を作成する：

```
gh issue create \
  --title "<課題の簡潔なタイトル>" \
  --body "## 概要\n<何が問題か>\n\n## 発見箇所\n<ファイルパス:行番号>\n\n## 改善案\n<どう直すか>" \
  --label "AI調査結果確認待ち"
```

- 1つの調査セッションで作成するissueは最大5件
- 既存のオープンissueと重複しないか `gh issue list --state open` で確認してから作成
  - 以下のいずれかに該当する場合は**重複とみなしスキップ**する（issue を作成しない）：
    1. 既存issueの本文に同じファイルパスが含まれている（発見箇所が一致）
    2. タイトルが概ね一致し、同じバグ・同じ機能・同じ改善点を指していると判断できる
    3. 既存issueが対象の問題を包含している（スコープが広い既存issueがある）
- 軽微な typo 修正などは issue 化せずスキップ

# タスク: issue分割（task=split）

スコープが大きすぎる既存issueを、独立して実装可能な子issueに分割する。

## 分割手順

1. `gh issue view <number> --comments` で対象issueの本文・コメントをすべて取得する
2. 独立して実装可能なサブタスクに分解する（2〜4件が目安）
   - 各サブタスクは「1ブランチ・1コミット・1PR」で完結できるスコープにする
   - 依存関係がある場合は実装順序を明記する
3. 各サブタスクを新規issueとして作成する
   ```
   gh issue create \
     --title "<サブタスクのタイトル>" \
     --body "## 概要\n<何をするか>\n\n## 元issue\n#<元issue番号> から分割\n\n## 発見箇所（該当する場合）\n<ファイルパス:行番号>\n\n## 実装方針\n<どう実装するか>" \
     --label "AI調査結果確認待ち"
   ```
4. 元issueに分割結果をコメントする
   ```
   gh issue comment <number> --body "スコープが大きいため以下の子issueに分割しました。\n\n- #<子1> <タイトル>\n- #<子2> <タイトル>\n\n承認後、子issueを順に実装します。"
   ```
5. 作成した子issue番号のリストを呼び出し元に返す
